# 月度闹钟

把「每月 8 号交电费」这类周期性日子变得可靠。开源免费、无广告的 Android 月度提醒/闹钟应用，离线运行，不自带账号、不上传提醒内容。

> 适用 Android 8.0 及以上 · 不需要注册登录 · 不申请联网权限

## 它解决什么问题

手机自带的闹钟大多只能设「每天」或「每周几」，一次性提醒又要每次手动新建。生活里真正容易忘的，偏偏是那些**每月才来一次**的日子：

- 每月 8 号交电费，因为这天有 7 折
- 每月 20 号还信用卡、花呗
- 每月最后一天交房租、做月度结算
- 每月第二个周二开部门例会
- 每年 3 月 15 日报税、每年某日续保

月度闹钟把这些规则一次性设好，之后到点全屏响铃，不用再记。

## 使用场景

| 场景 | 推荐规则 | 说明 |
| --- | --- | --- |
| 每月固定日期缴费 | 每月某日 1–31 | 当月没有 31 号时按规则跳过，不会莫名提前 |
| 月底结算、交房租 | 每月最后一天 | 自动适配 30/31 天和闰年 2 月 |
| 每月第几个周几 | 每月第 N 个星期几 | 例如「第二个周二」「最后一个周五」 |
| 信用卡还款日 | 每月某日 + 提前结束条件 | 可设剩余次数，换卡后不用记着关 |
| 年年重复的纪念日/续费 | 每年某月某日 | 2 月 29 日只在闰年触发 |
| 单次重要事项 | 单次 | 精确到分钟，响过自动关闭 |
| 每天吃药、打卡 | 每天 / 工作日 | 工作日为周一至周五 |
| 每周固定几次 | 每周多选 | 可同时选周一、周三、周五 |

## 功能

### 重复规则

- **单次**：精确到年、月、日、时、分
- **每天**
- **工作日**：周一至周五（首版，不含中国法定节假日与调休）
- **每周**：可多选星期
- **每月某日**：1–31 日；当月没有这一天时跳过，不自动改到月末
- **每月最后一天**：自动适配大小月和闰年二月
- **每月第几个星期几**：第一个到第四个、最后一个
- **每年某月某日**：2 月 29 日在平年跳过，下一次落在闰年

### 提醒与结束

- 结束条件：永不 / 指定结束日期 / 剩余次数（1–365）
- 编辑页展示接下来三次提醒，保存前即可检查规则
- 首页只展示每个提醒的下一次，按时间排序；其余提醒在「接下来」中列出
- 开关用于暂停/恢复；单次提醒触发后自动关闭
- 全屏响铃：息屏时自动亮屏并弹出响铃页，贪睡（默认 10 分钟，可在设置中调为 1–120 分钟）、停止；全屏通知被厂商拦截时由响铃服务直接拉起页面兜底
- 音量加/减键可直接贪睡
- 震动开关：开启后按 `USAGE_ALARM` 通道循环震动（震动/静音模式同样生效），关闭则不震
- 系统默认铃声，响铃页配色、字体与主界面一致，深浅色跟随系统
- 开机、时间变更、时区变更后自动重排
- 精确闹钟权限缺失时降级为约 60 秒窗口，并在首页提示权限问题

### 后台可靠性与锁屏

- **到点由系统自己拉起响铃服务**：每次登记触发都做两层，和系统自带时钟的做法一致——`setAlarmClock`（状态栏「下一次闹钟」芯片，广播）加 `setExactAndAllowWhileIdle` 指向 `RingtoneService` 的 `getForegroundService` PendingIntent。后者不经过本应用的广播接收器，也不需要进程提前存在，这正是自带闹钟不必常驻后台的原因；前者在 OEM 冻结进程后可能永远不送达
- **同一档期只响一次**：两层会在同一分钟先后到达，先到的那一次推进排期并响铃，后到的按 90 秒档期去重合并，不会响两遍也不会静默跳一个月
- **记账与事后补响**：每次排闹钟都记下「答应过系统几点响」，每次醒来核对；发现某个时刻已过却从未触发，就在 12 小时窗口内补响一次，而不是等下个月
- **每次进程启动都自愈**：打开应用、开机、改时间、改时区后，把所有已启用的提醒重新排一遍；审计先于重排，否则证据会被下一次触发时间覆盖
- **精确闹钟权限恢复即重排**：Android 12+ 撤销 `SCHEDULE_EXACT_ALARM` 会停止应用并取消所有精确闹钟，应用监听 `SCHEDULE_EXACT_ALARM_PERMISSION_STATE_CHANGED` 在重新授权后立刻补排
- **响铃被杀也能回来**：响铃服务声明 `START_STICKY` 并把「正在响哪一条」带时间戳写盘；服务被杀后系统重启它会回到同一条提醒的响铃页，超过 6 分钟的旧记录直接作废，不会半夜凭空响
- **兜底一定有声音**：前台服务起不来时改走的通知渠道带闹钟音频属性、可穿透勿扰；此前这条兜底是静音渠道，等于什么都没发生
- **重排不会吃掉贪睡**：重排只清基础闹钟，不再取消进行中的贪睡
- **可选的「多一层保险」**：设置页的常驻前台服务开关默认开启，让进程尽量别被杀、省掉重建开销；它已不是提醒能否响的前提，关掉不影响响铃。另有 `JobScheduler` 15 分钟周期校检与六小时心跳，作为同一条队列的额外看护
- **锁屏直接关闭**：响铃页 `showWhenLocked` + `turnScreenOn` + 清单里的 `showOnLockScreen` + `DISABLE_KEYGUARD`，不请求解除锁屏，因此锁屏上就能点「停止 / 贪睡」，不会被 PIN 键盘盖住
- **全屏提醒有独立 PendingIntent**：全屏提醒与点通知用不同 action 和 requestCode，否则系统会按同一请求去重，全屏提醒会退化成普通通知
- **解锁即到前台**：响铃期间注册一次 `ACTION_USER_PRESENT` 广播（平时不监听），解锁瞬间主动拉起响铃页
- **打开应用落到响铃页**：正在响铃时点图标直接进关闭页，由 ring token 判断，贪睡后再次响铃同样生效
- **运行记录**：设置页底部是本机响铃流水账（进程启动、排闹钟成功/失败、系统直接唤起服务、重复投递合并、心跳、作业校检、补响、关闭），最多 240 行，可随时清空
- **设置页引导**：省电白名单、自启动、最近任务锁定三件事的说明与一键跳转，另有「10 秒后响铃」用于真机自测，不改动任何提醒时间
- **60 秒实测：真的能响吗**：设置页「清后台还响不响」会用一个真实提醒排一次一分钟后的响铃，然后请用户把应用从最近任务划掉。铃声到达时比对进程代号——只有进程真的死过一次，才说明是系统自己把服务/广播拉起来的，也就是「清后台也响」；进程没死就只算「响了，但这次没测到清后台」。四种结果（通过 / 响了但没测到 / 响了但迟了很久 / 没响）分别给不同建议，不把「迟到」当成「通过」
- **实测不靠猜**：国产 ROM 的自启动开关没有公开 API 可读，因此本应用不谎称读到状态，只用实测反推；试响和实测使用互不干扰的两个 `PendingIntent` 身份，取消其中一个不会顺手取消另一个；排期后超过半小时仍未回到前台的实测会被遗忘而不是判成失败，避免几周前的旧档期变成永久告警
- **漏响会在首页自己冒出来**：实测没通过、实测迟到、或记账发现某次到点没响，首页顶部会出现一条横幅，直接给「去设置自启动」的按钮

## 安装

1. 从 [Releases](https://github.com/VanBuren-project/monthly-alarm/releases) 下载 `anqi-1.3.2.apk`（当前已发布版本），或使用自己构建的 `app/build/outputs/apk/release/app-release.apk` 传到手机。
2. 如果手机上装过 1.3.0 或更早的调试证书版本，先卸载再安装（签名不同，无法覆盖）。
3. 在系统设置中允许文件管理器/浏览器「安装未知应用」。
3. 安装并打开「月度闹钟」。
4. 首次进入按首页提示依次开启：
   - 通知权限
   - 精确闹钟（Android 12+）
   - 全屏提醒（Android 14+）
5. 设置页「后台守护 → 多一层保险」默认开启（状态栏会有一条安静的常驻通知）。它不是提醒能否响的前提，关掉也不影响响铃，只是应用被清理后要重新启动一次才恢复常驻。
6. **必须做的一步**：设置页 →「别让系统清掉它」→「三步就好」，依次做三件事：允许自启动、把省电策略改成「无限制」、在最近任务里锁定本应用。三个按钮会直接跳到对应页面（小米/红米、华为/荣耀、OPPO/一加/realme、vivo/iQOO、三星、魅族、华硕各有对应入口；找不到就退回应用信息页）。国产 ROM 的自启动开关无法被应用读取，做完后用下面的实测确认。不靠这三步也能响的前提是系统没有把应用冻住，而在小米、华为等机器上这个前提经常不成立。

### 第一次测试

先做设置页的「60 秒实测」：排期后立刻把应用从最近任务划掉，等它响。结果会直接写在卡片上——

- **通过**（进程被杀，仍由系统唤起）：这一步就已经过了，可以放心用
- **响了，但这次没测到清后台**：铃声来了，但没检测到进程冷启动，说明划掉的动作没生效或进程没真被杀，重新测一次
- **响了，但迟了很久**：系统把提醒压住了，去把省电策略改成「无限制」再测
- **没响**：多半是自启动没允许，按卡片上的按钮去打开

然后再点「10 秒后响铃」验证整条链路，并新建一个「单次」提醒设为 2–3 分钟后，锁屏等待。检查：

- 是否准时全屏亮起
- 锁屏状态下能否直接点「停止」或「贪睡」，无需先解锁
- 解锁后响铃页是否自己到前台
- 点「贪睡」后是否按设置分钟数再次响铃
- 点「停止」后是否安静
- 音量键是否能贪睡
- 从最近任务里划掉应用后，提醒是否仍然响
- 重启手机后提醒是否还在

若用命令行而没有设置 `ANDROID_HOME`，在仓库根目录新建 `local.properties`：

### 签名与密钥

- 正式密钥为 RSA 4096、有效期 100 年，使用 PKCS#12 格式的 `.jks`，别名 `monthly-alarm`。
- `app/build.gradle.kts` 从仓库根目录的 `keystore.properties` 读取签名信息；该文件和 `*.jks` 都在 `.gitignore` 中，源码仓库里只有构建逻辑，没有任何密钥材料。
- 自己构建时若没有 `keystore.properties`，release 构建会自动回退到 debug 证书，`assembleRelease` 仍可正常跑通。
- **密钥一旦丢失就无法再发布可覆盖安装的更新**，请把 `.jks` 与密码离线备份至少两份（例如加密压缩包 + U 盘）。

`keystore.properties` 格式：

```properties
storeFile=/absolute/path/to/monthly-alarm-release.jks
storePassword=你的密码
keyAlias=monthly-alarm
keyPassword=你的密码
```

后续发版流程：

1. 递增 `app/build.gradle.kts` 的 `versionCode` 与 `versionName`。
2. 用正式 keystore 构建：`./gradlew assembleRelease`（可选 `bundleRelease` 生成 AAB）。
3. 推送 tag 并上传 APK、`RELEASE_NOTES.md`、`SHA256SUMS.txt`。

若将来上架 Google Play，还需隐私政策 URL、Data safety 表单、512×512 图标、1024×500 特色图和内容分级。

## 已知限制 / 下一版

- 「工作日」目前只是周一至周五，尚未接入中国法定节假日和调休数据
- 日历只投影未来提醒，不保存独立的日历事件；已过去的日期不显示提醒点
- 贪睡中的临时提醒不会画在日历里
- 不支持自定义铃声选择（当前使用系统默认闹钟铃声）
- 不支持「跳过下一次」、提醒模板、历史记录、桌面小组件、云同步/备份
- 没有提前提醒、多个提前提醒、Wear OS
- 上架应用商店需要额外准备隐私政策、商店素材，并用 AAB 提交
- 未做 TalkBack 全量走查；已处理主要触控高度、字体缩放和窄屏溢出
- 常驻通知仍在，但已经是可选项：关掉「多一层保险」不影响响铃，只是应用被清理后要重新启动一次才恢复常驻
- **国产 ROM 的自启动开关读不到真实状态**：没有公开 API，应用无法判断那个开关到底开没开。所以本应用不谎称知道，只用「60 秒实测」从结果反推——真的响了才算过。找不到对应自启动页面的品牌会退回系统应用信息页，仍需手动找到「自启动」入口
- **强制停止无法自动恢复**：被系统 force-stop 的应用（含「清理后台」等价于强停的 ROM）不能执行任何代码，任何第三方应用都无法在被强停期间自行恢复。这版按系统自带时钟的做法改用「精确闹钟 + 服务 PendingIntent」交投递，不再依赖进程常驻；但小米/HyperOS 的清理会把应用**冻结**，冻结期间连投递都不发生，这是 1.3.6 用「三步设置 + 实测」来绕开的部分，而不是代码能消除的部分
